# ADR-P11: CI serves PHP 8.4; PHP 8.3.35 segfaulted on the GitHub runner

**Status:** accepted (2026-10-07)

## What happened

On GitHub's Ubuntu runner, PHP 8.3.35 crashed under load while serving Accord: a segfault inside
the engine, in `zend_std_get_static_property_with_info` (reading a class's static property), always
at the same instruction. It hit `php -S` workers and PHP-FPM workers alike, with opcache on or off,
with only the needed extensions loaded, and on requests with and without JWT verification. The same
PHP build never crashed locally or in an Ubuntu 24.04 container. Accord's own code reads no static
property on these paths; dependencies (php-jwt, Laravel) do, as most PHP code does.

## Decision

- The jobs that run servers (conformance, mixed fleet, frameworks) use PHP 8.4, served by PHP-FPM
  behind nginx (tools/conformance/fpm-nginx.sh), as in production. They pass.
- Unit tests still run on 8.3 and 8.4, and `php: >=8.3` is unchanged.
- The control API runs as a plain CLI process (control-server.php), never under `php -S`.

## Consequences

Run Accord on PHP 8.4 where possible. On 8.3, watch for worker segfaults (`signal 11` in the FPM log);
FPM restarts the worker, the client sees a failed request and retries, and no data is lost (pushes
are idempotent), but requests fail. If one is reproduced outside CI, report it to php-src with a
backtrace.
